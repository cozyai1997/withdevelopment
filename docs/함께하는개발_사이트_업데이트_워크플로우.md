# 함께하는개발 사이트 업데이트 워크플로우

## 1. 업데이트 목표

함께하는개발 사이트의 홈 화면은 스크롤을 내리며 주요 메뉴를 빠르게 훑는 요약 포털로 운영한다. 단, 모든 정보를 한 페이지에만 담는 단일 롤링 사이트가 아니라, 각 메뉴는 독립 URL과 상세 페이지를 유지한다.

핵심 방향은 다음과 같다.

- 홈에서는 회사 소개, 서비스, 시공 실적, 공지사항, 자료실, 문의 흐름을 순서대로 미리 보여준다.
- 각 홈 섹션은 상세 페이지 또는 게시판으로 이동하는 명확한 링크를 가진다.
- 모바일 사용자는 세로 스크롤만으로 업체 신뢰도, 서비스 범위, 시공 실적, 문의 경로를 확인할 수 있어야 한다.
- 시공 실적은 첫 화면과 중간 섹션에서 카드형 갤러리로 반복 노출한다.
- 개인정보, 상세 주소, 개인 연락처, 사업자 식별정보, 차량번호, 얼굴은 공개 전 검수한다.

## 2. 홈 화면 정보 구조

홈은 아래 순서로 구성한다.

### 2.1 첫 화면

첫 화면은 광고 유입 사용자가 바로 신뢰 요소와 문의 경로를 확인할 수 있게 구성한다.

- 회사명: 함께하는개발
- 핵심 메시지: 철거 전문성, 현장 중심 수행, 빠른 문의 가능성
- 주요 CTA: 문의하기, 서비스 보기
- 시공 실적 카드형 갤러리: 대표 실적 1개와 보조 실적 2~3개

첫 화면에서 보여줄 시공 실적 카드는 짧고 빠르게 읽히는 형식으로 작성한다.

```text
리모델링 철거
서울권 · 상가 내부 철거
마감재 철거 · 폐기물 정리
자세히 보기
```

이미지가 준비되지 않은 경우에는 텍스트형 현장 로그 카드로 운영한다. 이미지가 준비된 경우에는 얼굴, 차량번호, 상세 주소가 제거된 사진만 사용한다.

### 2.2 서비스 요약

서비스 요약 섹션은 4개 카테고리를 카드형으로 배치한다.

- 구조물 철거
- 리모델링 철거
- 철거 대관업무
- 재개발·재건축구역 철거

각 서비스 카드는 2~3줄 설명과 상세 페이지 링크를 가진다. 홈에서는 서비스 전체를 설명하지 않고, 사용자가 자신의 상황에 맞는 메뉴로 이동하도록 유도한다.

### 2.3 시공 실적 갤러리

시공 실적 섹션은 홈의 핵심 신뢰 영역으로 운영한다.

- 대표 실적 1개는 크게 배치한다.
- 추가 실적 3~5개는 동일한 카드 규격으로 배치한다.
- 각 카드는 카테고리, 지역 단위, 공사 유형, 작업 범위, 상세 보기 링크를 포함한다.
- 전체 목록은 `/cases`로 연결한다.

카드 안의 정보는 다음 필드를 기준으로 작성한다.

```text
카테고리
지역 단위 · 공사 유형
작업 범위 1줄 요약
상세 보기
```

상세 주소, 발주처명, 사람 얼굴, 차량번호는 노출하지 않는다.

### 2.4 업무 흐름

업무 흐름은 모바일에서 세로 스텝으로 읽히게 구성한다.

1. 현장 조건 확인
2. 작업 범위 협의
3. 일정과 안전 계획 정리
4. 철거 진행
5. 정리와 후속 안내

이 섹션은 사용자가 문의 전에 무엇을 준비해야 하는지 이해하도록 돕는 역할이다.

### 2.5 공지사항과 자료실 미리보기

공지사항과 자료실은 홈에서 최신글 2~3개만 보여준다.

- 공지사항은 운영 안내와 중요 공지를 노출한다.
- 자료실은 철거 준비 체크리스트, FAQ, 문의 전 확인사항을 노출한다.
- 각 섹션은 전체 보기 링크를 통해 `/notice`, `/resources`로 이동한다.

### 2.6 문의 섹션

문의 섹션은 홈 하단에서 다시 한 번 CTA를 제공한다.

- 전화 문의
- 문자 문의
- 카카오톡 문의
- 문의 전 준비사항 안내

공식 대표번호와 카카오톡 채널이 확정되기 전에는 자리표시자로 유지한다.

## 3. 카드형 갤러리 운영 기준

시공 실적 카드는 화려한 장식보다 정보 전달과 신뢰 형성에 집중한다.

### 3.1 카드 구성

각 카드는 다음 요소를 포함한다.

- 서비스 카테고리
- 지역 단위
- 공사 유형
- 작업 범위
- 공개일 또는 등록일
- 상세 페이지 링크

이미지 사용 시에는 카드 상단에 1장을 배치한다. 전후 사진을 사용할 경우, 모바일에서 이미지가 너무 작아지지 않도록 한 카드에 사진을 과하게 넣지 않는다.

### 3.2 배치 방식

데스크톱에서는 대표 카드와 보조 카드를 혼합한다.

```text
[대표 실적 큰 카드] [실적 카드]
[대표 실적 큰 카드] [실적 카드]
                 [실적 카드]
```

모바일에서는 한 줄 1카드 또는 가로 스크롤 레일 중 하나를 선택한다.

- 홈 첫 화면: 가로 스크롤 레일을 우선 검토한다.
- 홈 중간 시공 실적 섹션: 세로 1열 카드 목록을 우선 검토한다.
- CTA는 카드 목록 아래에 배치한다.

### 3.3 디자인 제한

기존 디자인 조건을 유지한다.

- 폰트: Pretendard
- 색상: `#101820`, `#F7F4EE`, `#D6A21A`, `#FFFFFF`
- 카드에는 임의의 회색, 파랑, 빨강을 추가하지 않는다.
- 텍스트 박스는 섹션 배경과 같은 색으로 처리한다.
- border, outline, box-shadow, SVG stroke를 사용하지 않는다.

카드형 갤러리는 떠 있는 카드 느낌보다, 배경 위에 정돈된 정보 블록처럼 보이게 구성한다.

## 4. 게시판 업데이트 흐름

### 4.1 시공 실적 등록

관리자는 `/admin`에서 시공 실적 게시글을 작성한다.

필수 입력값은 다음과 같다.

- 게시판: 시공실적
- 제목
- 슬러그
- 요약
- 본문
- 공개 상태

본문에는 다음 순서로 작성한다.

1. 공사 유형
2. 지역 단위
3. 작업 범위
4. 진행 방식
5. 문의 CTA 문장

공개 전 반드시 개인정보 검수를 진행한다.

### 4.2 공지사항 등록

공지사항은 운영 변경, 서비스 안내, 사이트 공지 중심으로 작성한다.

- 제목은 짧고 명확하게 작성한다.
- 본문은 핵심 안내와 필요한 문의 경로만 포함한다.
- 민감 정보나 내부 운영 정보는 공개하지 않는다.

### 4.3 자료실 등록

자료실은 사용자가 문의 전에 준비할 정보를 제공한다.

권장 주제는 다음과 같다.

- 철거 문의 전 체크리스트
- 리모델링 철거 준비사항
- 철거 대관업무 진행 전 확인사항
- 현장 사진 전달 시 개인정보 제거 방법

법률 자문처럼 보이는 단정 표현은 피한다.

## 5. 모바일 대응 기준

모바일은 홈 스크롤 경험을 기준으로 검수한다.

필수 확인 항목은 다음과 같다.

- 360px 화면에서 텍스트가 겹치지 않는다.
- CTA 버튼은 44px 이상의 터치 영역을 가진다.
- 첫 화면에서 회사명, 핵심 메시지, 문의 CTA가 보인다.
- 시공 실적 카드는 한 번에 너무 많은 정보를 넣지 않는다.
- 메뉴는 줄바꿈되어도 읽기 순서가 자연스럽다.
- 가로 스크롤이 필요한 영역은 카드 레일처럼 의도적으로 구성한다.
- 페이지 전체에 의도하지 않은 수평 overflow가 없어야 한다.

검수 화면 폭은 최소 360px, 768px, 1440px로 확인한다.

## 6. SEO와 전환 추적 기준

각 독립 URL은 고유한 제목과 설명을 가진다.

- `/`: 함께하는개발 철거 서비스 요약
- `/services`: 서비스 전체 안내
- `/cases`: 시공 실적 목록
- `/notice`: 공지사항
- `/resources`: 자료실
- `/contact`: 문의 안내

시공 실적 상세 페이지는 동일한 문구를 반복하지 않고, 지역 단위와 공사 유형을 반영한 고유 설명을 작성한다.

전환 이벤트는 공식 채널 확정 후 연결한다.

- 전화 클릭
- 문자 클릭
- 카카오톡 클릭
- 문의폼 제출

추적 스크립트나 광고 파라미터는 환경변수 또는 광고 계정에서 관리하고, 공개 문서나 코드에 민감 값을 남기지 않는다.

## 7. 업데이트 QA 체크리스트

업데이트 후 아래 항목을 확인한다.

- 홈에서 여러 메뉴를 스크롤로 훑을 수 있다.
- 각 메뉴는 독립 URL로 이동한다.
- 첫 화면 또는 첫 화면 직후에 시공 실적 카드형 갤러리가 보인다.
- `/cases`, `/notice`, `/resources` 목록과 상세 페이지가 정상 동작한다.
- 관리자 권한이 없는 사용자는 `/admin`에 접근할 수 없다.
- 공개되지 않은 게시글은 상세 페이지에서 노출되지 않는다.
- 색상은 허용된 4가지 HEX만 사용한다.
- 텍스트 박스와 카드에 border, outline, box-shadow, stroke가 없다.
- 360px, 768px, 1440px에서 텍스트 겹침과 수평 overflow가 없다.
- 대표자명, 개인 연락처, 사업자 식별정보, 상세 주소, 얼굴, 차량번호가 공개되지 않는다.

## 8. 배포 전 확인

배포 전 다음 순서로 확인한다.

1. `npm run typecheck`
2. `npm run lint`
3. `npm run build`
4. 주요 라우트 접속 확인
5. 모바일 화면 확인
6. 개인정보 노출 검수
7. Supabase RLS와 관리자 계정 확인
8. Vercel 환경변수 확인
9. 도메인과 SSL 확인
10. 검색엔진과 광고 연결 확인

## 9. 운영 원칙

홈은 사용자가 빠르게 판단할 수 있는 요약 페이지로 운영한다. 상세 정보는 독립 페이지와 게시판에 축적한다.

시공 실적은 가장 강한 신뢰 요소이므로 홈 첫 화면, 중간 갤러리, `/cases` 게시판에서 반복 노출한다. 단, 공개 가능한 범위만 사용하고 개인정보 보호 기준을 우선한다.

모바일에서는 사용자가 메뉴를 여러 번 누르지 않아도 홈 스크롤만으로 서비스 범위와 문의 경로를 이해할 수 있어야 한다.
